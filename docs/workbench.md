# 文稿工作台与本轮工程验收

## 本机运行

```bash
uv sync --locked --extra web
uv run --locked --extra web python -m workbench
```

默认仅监听 `127.0.0.1:8780`。这是维护者的源码运行入口；普通用户免安装的网址交付尚待部署决定。
本地审计默认按规则显示重点。装 `--extra models` 并设置 `ACCEPTANCE_DESK_MODEL_CACHE` 后，可以使用缓存中的 NLI 与句向量作补充。每处修改都由作者决定。[可选模型配置](../experiments/step1_models.md)

## 使用

1. 粘贴或上传相邻两版 UTF-8 文稿，上传支持 BOM。两侧各选 txt 或 Markdown；Markdown 按源文本检查，不执行其中的 HTML。
2. 如需接续旧页面或另一台机器的审阅，在载入页选择进度 JSON，再开始检查；已在工作台中时点正文上方的“恢复进度”。进度文件不含全文，需要同时提供相同的两份文稿。
3. 连续正文用于逐处验收；并排对校始终显示两版源文本，各保留原有空白。点任一侧修改都可同步右栏。作者的编辑结果单独显示，不改写两列源文本。
4. 批量操作只作用于当前筛选内的待定项，确认框先列出条数与编号；已编辑或已决定项不动。撤销按整批恢复，包括备注、决定人和时间。
5. 导出时可选择文字修改之外的空白跟随决定、统一用原稿或改稿排版；没有文字修改时仍单列排版差异。Markdown 的缩进、换行和代码块风险使用核心提示，不能替代完整 Markdown 解析。
6. 有待定项时导出的是草稿，待定处理策略可选；作者意见由核心 `feedback_markdown` 生成。下载和保存进度均在本机执行。

恢复会核对文稿哈希、修改数、编号、位置、文本与合法决定；校验成功后整份替换并清空撤销历史，失败保留当前决定和原存档。加载其他文稿前保留上次本机存档，直到新文稿成功载入。

## 审阅优先项

「出处待核对」显示仅见于一版全文的出处标记，包括原文写法。两稿之间搬移了相同写法的出处时，这个筛选不会突出显示该处。显式启用 run03 时，左上角的问号解释历史模型和筛选的来源。

## 生成新稿

macOS 应用打开时提供「跳过」与「开始引导」。也可从导入页的「打开示例」选择短文或长文。导入支持拖放、文件选择和粘贴。已有文稿可从「继续上次审阅」恢复。

点击「生成新稿」，在同一个面板里完成修订、模型、确认三步。

1. **修订**。选局部修订或整体改写。逐处写下的修改建议全部自动发送，每条建议可以修改它所在的那一处。局部修订会核对其他已确认内容。整体改写时，已采用的措辞供参考，明确保留、手工编辑或删去的内容仍会核对。还可以选择是否附上没有建议的待定位置作参考。
2. **模型**。选择本机 CLI 或 API，核对连接和模型。已有连接可以继续使用。
3. **确认**。界面直接列出你的全部建议。可展开合并稿、定位资料和完整请求。也可核对将发送的学术修订参考。确认后才发送。模型须返回完整正文和每条要求的执行说明。返回原文或缺少执行说明时，程序自动重试一次。仍未修改或存在未执行的要求时，界面显示原因，并禁止开始下一轮。

「修订」中的「学术修订参考」有两项：论证与证据、概念与表述。默认均未勾选，可展开查看指引原文和来源。选中的指引会随本轮修订请求发给所选 CLI 或 API，也会用于候选稿的后续对话。指引只适用于作者指定的修订范围，作者的明确要求优先。开始下一轮后，可以从上一轮的「已发送的修改意见」查看当时发送的指引原文。

右侧「修改意见」像聊天输入框一样使用，写清要改什么、怎么改，再点「交给模型修改」。该按钮会汇总全文的全部建议，并进入上述核对流程。无需把已决定的条目改回待定。

候选稿下方可以继续写补充要求并发送，也可以重新生成。补充要求与上一份候选稿一起交给模型，较新的明确要求覆盖较早的冲突要求。缺少事实依据时，模型应指出所需材料，不能编造引文或页码。作者有排版要求时，不再由程序强制恢复旧空行。

逐条说明由模型提供，不能代替正文验收。程序检查是否遗漏回应、是否返回原文、是否报告了未执行的要求。候选稿改动了其他已确认内容时，工作台会并排显示两种写法。可以逐处同意覆盖，或补充要求让模型重改。确认只对当前候选稿生效。模型连接用于生成新稿，本地审阅雷达在导入时独立运行。

推理强度跟随所选模型。Codex 读取模型目录中的强度及快速档，OpenCode 读取模型变体，Pi 使用模型目录里的思考能力。Antigravity 优先保留 CLI 给出的完整模型 ID。目录同时提供基础 ID 和档位变体时，可单独选择强度。已知支持档位的 Claude、OpenAI、Gemini 和 DeepSeek 接口也会显示选项。选择会随模型和连接地址记住。

点击轮次可回看历史改稿及当轮裁决。「已发送的修改意见」保留目标模型、新生成轮次的修订范围、待定处理方式、补充对话、模型执行说明、作者确认覆盖的条目和时间。

### CLI 兼容范围

本机适配思路参考 [OpenDesign 固定版本的运行时注册表](https://github.com/nexu-io/open-design/blob/e033aad1d15a9d4084316e5223f2c6597fd32619/apps/daemon/src/runtimes/registry.ts)。验收台的本机 CLI 菜单面向一次性整稿生成。OpenDesign 中的其他 ACP、插件和自动执行工具需要不同的权限与会话处理，因此没有注册为可生成新稿的 CLI。DeepSeek、Moonshot、Mistral、xAI 和 MiMo 可以直接从 API 供应商连接。旧 Gemini CLI 的对应入口是 Antigravity 或 Gemini API。

CLI 能复用该工具已有的账户和供应商配置。工作台为每次调用创建临时工作目录，并用所选 CLI 的可用选项约束工具执行。不同 CLI 对本机历史记录有各自的设置。文稿通过标准输入传给 CLI。对于 Antigravity，验收台经 `agy` 一次性指定模型，检测到当前 CLI 不支持所需选项时会提示版本问题。

## 快捷键与编辑草稿

工作台支持 Command/Ctrl+S 保存当前进度，Command/Ctrl+Z 撤销决定，Command/Ctrl+Shift+Z 或 Ctrl+Y 重做，Option/Alt+↑/↓ 移动到上一处或下一处，⌘/Ctrl+K 按编号或摘要定位。长文右侧的标尺把待定位置按文稿长度分组，点击即可跳转。采用、保留和撤销后，目录、正文和侧栏会同步定位，键盘焦点留在可继续操作的控件。多行编辑区使用独立的文字撤销历史：一次中文选词提交为一步，连续多次提交分别撤销；粘贴、选中替换、选中删除各自成步，撤销恢复对应光标或选区。未提交的候选拼音不作为正文保存。查找框仍用浏览器原生编辑。编辑弹窗中 Command/Ctrl+S 与“保存”按钮一致，提交编辑结果。

备注和编辑草稿在输入停止约半秒后自动保存。工具栏显示保存中、已保存、保存失败可重试或仅本页保存；文件存储写入得到确认后才显示已保存。“关闭”编辑弹窗保留草稿，“放弃草稿”清除草稿。空白草稿也会保留，点击保存后用于删除该句。关闭本机保存时草稿仅留在当前页面。

本机恢复包含当前修改、正文/对校视图、修改搜索和备注筛选。撤销与重做历史只保留在当前页面。下载的进度 JSON 继续使用原有协议，包含已提交的决定和备注，本机编辑草稿保存在工作台存档中。

左栏可搜索修改中的原句、改句、编辑结果和修改意见，并筛选带意见的修改。顶部“预览”使用与导出相同的合并逻辑，可选择待定处采用哪一版和空白排版策略。

### 浏览器适配的构建

业务、保存和浏览器适配均以 Python 编写。多行编辑区复用 NiceGUI 自带的 CodeMirror；`workbench/browser/prose_history.py` 为其安装撤销分组规则，规则函数在 `workbench/history_policy.py` 中，并由 Python 单元测试覆盖。浏览器运行文件由 Transcrypt 3.9.5 自动生成，位于 `workbench/assets/prose/`，不要手改生成物。

```bash
uv run --with transcrypt==3.9.5 python tools/build_prose_history.py
```

生成文件与运行库随安装包发布，正常运行无需 Transcrypt，也不会从外网加载编辑器适配。修改分组规则后需重建生成文件。真实 macOS 拼音候选窗仍需人工验收，浏览器模拟组合输入不能代替它。

先启动工作台，可用独立 Chrome 会话检查快速中文提交、逐步撤销/重做、输入期间控件不重建、括号和 Tab 行为：

```bash
uv run --with playwright python tools/check_prose_editor.py --url http://127.0.0.1:8780
```

文字输入不改变决定进度，也不逐字重建目录或历史按钮；只有搜索、意见筛选依赖文字内容时才更新目录，自动保存仍按停顿合并。

2026-11-15 本机验收：Python 测试 986 通过、9 项因可选模型缺失跳过；可信组合输入回归覆盖快速三段中文、逐次撤销/重做、emoji 选区恢复与候选内容隔离。普通输入与撤销场景中，目录、进度条和历史按钮的重复重建由各 12 次降到 0。用户使用 Safari 与 macOS 自带拼音复验后确认：“已明显顺畅，撤销粒度也正常”。

## 修改目录与页面缩放

筛选按“全部 / 待定 / 重点 / 其余”排序。新审阅默认显示全部，旧存档继续恢复原有筛选。窄侧栏的筛选以两行显示，空间充足时排成一行，条目决定状态放在摘要下方。撤销与重做使用回转箭头，保留文字提示和快捷键。

页面放大或窗口变窄时，顶部“修改目录”按钮打开可滚动目录。选择修改后自动收起，也可按 Esc 或点击关闭按钮收起。关闭后焦点回到「修改目录」。

## 外观

载入页和工作台右上角的外观按钮提供“跟随系统 / 浅色 / 深色”，默认跟随系统。选择按浏览器单独保存，切换外观、切换文稿和刷新页面均保留选择。外观设置与文稿保存开关独立。

正文使用独立的纸页底色，深色下的增删标记、证据和控件分别配色。支持 `corner-shape` 的浏览器使用平滑圆角，其他浏览器使用标准圆角。中等窗口优先留出正文空间，超宽窗口显示页边批注，窄屏对校逐组标明原稿与改稿。

## 本机保存

载入页和导出面板均可关闭保存。关闭时删除本浏览器对应的工作台存档，随后操作只留在当前页面；离开前需下载进度文件。开启时保存两份全文、格式与作者决定，刷新可接续。默认目录 `~/.acceptance-desk/web-storage`，由 NiceGUI 管理，可用 `NICEGUI_STORAGE_PATH` 指定目录。

存档在运行服务的机器上，当前按浏览器标识区分；这不等于公网多用户隔离设计。公开部署前，账号、隔离、保留期限和服务端论文处理方式需另定。
