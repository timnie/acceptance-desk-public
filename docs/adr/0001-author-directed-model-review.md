# ADR 0001 采用作者自选模型，按作者意图审阅论证变化

状态：已采纳为开发方向，待实现和验证。

决策日期：2026-11-23

## 决策

在新的默认流程中，作者先通过 BYOK 选择自己的模型连接。该模型承担后续改稿、修改分类和论证分析。Acceptance Desk（AD）提供一套可跨模型使用的审阅指令（Skill），负责组织审阅材料、核对文本位置，并保存作者的决定。run03 退出新流程的默认审阅路径，冻结模型、阈值和既有评测结果作为对照保留。

现有桌面版已经支持选择模型、编辑修订指令和生成候选稿。导入时的本地审阅雷达独立运行。下一阶段复用已有模型连接，将审阅作为一次单独的调用接入工作台。[工作台现状](../workbench.md#生成新稿)

## 为什么改变方向

离线分类器可以提示优先审阅的条目。要判断某处变化是否符合作者意图，工作台还需要原稿、改稿及本轮要求，并把模型的依据定位到正文。

原设计假定作者看到证据，就能按稳定的写作意图作出判断。实际审阅还要求作者回忆本轮目的、找回支撑主张的材料，并判断采纳改动后需要为哪项结论负责。改稿时推迟的这些判断，在多轮验收时可能累积为认知负担。决定日志能说明谁批准了修改，原稿、候选稿和模型输出也让决定可以复查。把批准记录当成作者已理解后果，就会产生监督已经奏效的错觉。作者理解了多少，仍需通过真人试用检验。

继续优化 run03 可以减少部分待阅条目。让作者自选模型也可以省去团队持续训练通用分类器的工作。这两种变化都没有直接回答一个问题：这处改动是否符合这位作者此时想表达的主张？为回答它，改稿和审阅要共用作者确认的要求，工作台还要把受影响的论证关系呈现给作者。

## 一轮改稿怎样工作

1. **作者表达本轮意图。** AD 复用作者写下的修订指令和批注。只有一处歧义会影响实际取舍时，才请作者澄清。作者可把某项主张留待决定，也可在下一轮改变主张。AD 将确认过的要求与适用的稿件版本关联，模型推测的意图须标明来源。
2. **模型生成候选稿。** AD 将本轮要求和底稿交给作者选定的模型。候选稿进入版本对照，作者可以查看实际发送的要求。
3. **模型按 Skill 审阅。** AD 另起一次调用，提供两版文本、本轮要求和相关上下文。同一模型可以承担两次调用。Skill 要求模型对修改分类，指出受影响的主张、支撑材料和限定条件，给出两版文本位置，并把需要作者取舍的后果写成一个具体问题。缺少依据时，模型指出还需要查看哪份材料。
4. **作者作出决定。** AD 核对引文能否定位，并提供上下文供作者检查模型的解释。作者可以采用、保留原稿、自行编辑或暂缓。模型分类只影响审阅提示。下一轮涉及同一主张时，作者能回看当时的要求、证据和决定。

例如，原稿写「在受访的三家酒店中，交接延迟可能是原因之一」，候选稿改为「交接延迟是酒店服务延误的主要原因」。审阅应先检查样本限定是否移到了邻段，再检查新增材料能否支持「主要原因」。作者此时需要决定的是「要保留三家酒店的观察范围，还是有依据把结论扩大到其他酒店？」如果作者主动扩大了范围，下一轮应以更新后的意图审阅。

## 代价与验证

模型选择权交给作者后，同一份 Skill 可能得到不同分类。生成和审阅使用同一模型时，两次调用也可能重复同一种误读。AD 需要记录实际使用的模型、本轮指令和 Skill 版本，使问题可以追查。模型给出的解释始终可由作者质疑和纠正。

首轮验证聚焦「结论范围是否改变」。选取新的真实稿件，覆盖三种情况：结论确实扩大、限定仅移到别处、作者有意扩大结论且补充了证据。先人工写出双侧证据和审阅问题，观察这些材料能否帮助作者判断，再用两种模型运行同一份 Skill，检查误报和遗漏。

比较现有工作台和新流程时，记录作者能否用自己的话说清主张发生了什么变化、证据支持到哪里，以及为何采用或退回。同步记录判断用时和作者很有把握却误批准的情况。单轮试用检验当次理解。要判断认知负担是否随轮次减轻，还需观察后续改稿中，作者能否找回先前的理由，并在依据变化时更新决定。
